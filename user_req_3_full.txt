# PHASE 3 — IMPLEMENT REAL ENVIRONMENTAL VISUAL LAYERS

## 4. Create a proper environmental layer system

Implement a reusable layer catalogue. Users must be able to enable or disable individual layers, see their legends and inspect their data source and date.

At minimum, the interface should offer the following choices:

1. **Base map:** geographic reference and project location.
2. **Satellite true colour:** a real satellite-derived RGB image for the selected date or period.
3. **Vegetation / NDVI:** a calculated vegetation-index layer, based on the actual source bands.
4. **Water / NDWI or water mask:** a supported water-related visualization.
5. **Land cover:** a real source-backed land-cover layer when configured.
6. **Historical change:** a difference or change-candidate layer derived from the selected comparison.
7. **Project boundary:** declared/proposed/approved Zone A.
8. **Shadow footprint:** Zone B geometry and surrounding investigation context.
9. **Candidate findings:** the actual feature geometry and measurements from an analysis run.
10. **Optional contextual layers:** rainfall, fire, protected-area boundaries, terrain or other verified data where appropriate.

Some layers may require a configured provider. An unavailable layer must be visibly disabled with an explanation. Do not present the absence of a layer as an empty environmental result.

## 5. Environmental layer behaviour

Every layer must have:

- A name and description.
- A real data source or clearly labelled replay source.
- Data acquisition date or date range where applicable.
- Provider retrieval/processing time where available.
- Layer-specific legend and units.
- Opacity control where appropriate.
- An explicit source/availability status.
- A known limitations section.
- A loading state and useful error state.

Toggle actions must add, remove or change the actual corresponding source/layer on the map.

Do not use CSS backgrounds, decorative SVGs, random polygons or screenshots of maps as substitutes for data-backed layers.

Do not display a vegetation index unless the underlying raster values and bands used for the index are known. Do not display a historical change layer unless it was computed from identifiable observations or is prominently labelled as a replay visualization.

## 6. Real environmental data integration

Use the existing Earth Engine implementation if it works. Repair it rather than creating a parallel connector unnecessarily.

If the repository does not yet implement a functioning Earth Engine path, create one clean provider adapter using the official Python Earth Engine API.

For the initial live satellite comparison, use the Sentinel-2 surface-reflectance harmonized dataset:

`COPERNICUS/S2_SR_HARMONIZED`

Official dataset reference:

`https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S2_SR_HARMONIZED`

Requirements:

1. Validate the requested area of interest.
2. Validate the requested historical and comparison periods.
3. Query real available source observations.
4. Apply suitable quality masks.
5. Record the source IDs and actual acquisition dates.
6. Record the usable observation count and coverage.
7. Compute the supported index or composite through deterministic processing.
8. Produce the map visualization layer and numerical result.
9. Persist the analysis configuration and results.
10. Return source metadata, dates, status and errors to the frontend.
11. Render the result through the working MapLibre layer system.
12. Clearly distinguish live data from replay data.

If Earth Engine is not configured, show an actionable integration status and use an explicitly labelled replay case. The application must remain usable without cloud credentials.

Do not invent source IDs, acquisition dates, raster values, percentage changes, area measurements or environmental findings.

### Map-tile security and expiry

If Earth Engine map IDs or temporary tile credentials are used, manage them through the backend. Do not expose service-account credentials or private tokens in the frontend.

Handle expired tile identifiers by refreshing the relevant map visualization through the configured provider and reloading the source safely. Earth Engine's map APIs document the relationship between map IDs and tile requests, including the temporary nature of map identifiers.

Reference:

`https://developers.google.com/earth-engine/apidocs/ee-data-getmapid`

`https://developers.google.com/earth-engine/apidocs/ee-data-gettileurl`

## 7. Environmental calculations

Use deterministic processing for numeric and geospatial work.

For NDVI from the correct Sentinel-2 bands:

`NDVI = (B8 - B4) / (B8 + B4)`

Handle invalid pixels and zero/invalid denominators correctly.

The interface must not call an NDVI difference “forest destruction” without further evidence and a validated method.

Keep method thresholds configurable. Avoid a universal hard-coded rule presented as scientifically valid for every ecosystem or season.

Report separately:

- No candidate change identified by the configured method.
- Insufficient usable data.
- Provider unavailable.
- Analysis failed.
- Candidate change identified.

No usable data must never be reported as no environmental change.
